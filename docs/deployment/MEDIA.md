# 媒体资产：备份、恢复与旧目录

持久媒体在 `DATA_DIR/media`（compose 里是 `backend_data` 的 `media` 子路径）。
外链抓取缓存在 `CACHE_DIR/images`（`backend_cache`），可再生，不进灾备。

新上传、生成、编辑和联邦附件都写入媒体服务。Web 进程提供公开与鉴权读取；
联邦 worker 停掉不影响本站媒体。历史 `/media/federation/…` 与
`/api/phantasi/image-cache/…` 只通过已登记别名读取，不再从请求 URL 拼接磁盘路径。

## 备份与恢复

与 [BACKUP.md](BACKUP.md) 相同：Postgres + `backend_data` + `.env`。
不要挂 `backend_cache` 当恢复条件。生成图、人设、贴纸、手帐上传和联邦附件
应能从数据卷里的 `media/` 读回。旧公开地址靠别名，不靠缓存卷。

回滚到理解新资产模型的版本。不能拿任意更旧的二进制直接对着新库启动。
扩展阶段若仍保留旧列和旧目录，可回到兼容读的版本；新写入切换之后不行。

## 不要做的事

- 启动时扫描整个 `federation_media` 或 `cache/images` 当常规写入。
- 部署脚本里 `rm -rf` 清旧媒体目录来「完成迁移」。
- 把 image-cache 当永久素材备份。
- 未另行授权就对生产做破坏性迁移或删除旧副本。

## 执行旧媒体迁移

使用管理员登录态调用 `GET /api/media/migration` 查看进度，调用
`POST /api/media/migration`（JSON 请求体 `{}`）推进一批。每批最多处理 50 条，
游标与失败信息保存在 `media_migration_jobs`。请求结束后可停下，后续继续 POST 即可续跑，
不需要保持同一进程或浏览器连接。此接口受管理员鉴权保护，不接受任意目录或 SQL。

返回的 `progress` 包含：

- `pass`：0 为发现引用并登记旧资产身份，1 为复制和校验文件，2 为登记业务引用。
- `phase` 与 `after`：当前消费者阶段和游标；排序与续跑使用同一种文本排序。
- `scanned`：累计处理记录数；同一消费者在发现和引用阶段分别计数。
- `complete`：只有全部阶段成功才为 true。
- `error`、`error_source`：脱敏错误码和失败的表名/记录 ID。

只有 `success=true` 才继续下一批；发现 `error` 时先按记录 ID 修复缺失的旧文件或数据，
再以 `{}` 重试。失败批次不推进游标。不要通过删旧数据或跳过失败来标记迁移完成。
`{"restart":true}` 从头重新核对，已迁移文件和资产身份保持不变。

迁移先登记引用到的旧缓存文件，再复制已登记文件，最后核对手帐草稿/发布/历史、
人设、贴纸、联邦本地活动/待投递队列、未过期 AI 结果、可读渠道消息和 Agent 历史。
不扫描无引用的缓存目录；加密渠道消息不在宿主解密。未知或未迁移资产保持删除保护。
迁移期间新增或改写正文如引用尚未迁移的本地地址，会返回 `MEDIA_NOT_READY`；
完成迁移后重试该业务保存。本站绝对地址仅按配置的站点 origin 识别，外站同路径不导入。

完成后验证旧地址与新地址均可读取，再按备份流程备份 Postgres 与数据卷。
恢复验收应在不挂缓存卷的环境中进行。旧源文件不会被迁移自动删除。

## 自动恢复

现有进程维护循环每分钟最多恢复 16 个过期暂存资产，并重试最多 16 个删除中资产。
循环随进程退出取消，不额外创建永久后台进程。数据库断开时等待下一次维护。
写入每 200 秒续租；最终发布文件前持有资产行锁并核对写入令牌与租约。
过期 writer 被恢复任务接管后不能再发布文件。删除失败保留 `deleting`，后续维护重试。

## 回归测试

在可丢弃的 PostgreSQL 库上设置 `MYRIAD_MEDIA_TEST_DATABASE_URL` 后运行：

```sh
cargo test -p myriad-backend services::media:: -- --nocapture --test-threads=1
cargo test -p myriad-phantasi-notes
```

数据库测试各自创建独立 schema 并在成功后删除，不依赖现有业务数据。
未设置该变量时数据库测试会跳过，不能据此声称已完成数据库验收。
